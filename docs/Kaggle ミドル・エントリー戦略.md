# Kaggle ミドル・エントリー戦略ドキュメント

## 1. 目的と前提

* **目的**: 2025 年 7 月 31 日提出締切の Playground S5 E7 (タブラーデータ) で **銅メダル (上位 10 % 以内)** をソロで狙う。
* **前提条件**

  * ソロ参加、チーム参加はしない。
  * ディープラーニング手法は不使用。
  * データはスプレッドシート (CSV) 型。
  * コミット時間: 平日 4 h / 休日 8 h。
  * 対策 ML スタックは [https://github.com/kurosawa-kuro/solid-ml-stack](https://github.com/kurosawa-kuro/solid-ml-stack) に準備済み (LightGBM・CatBoost・XGBoost・Optuna・SHAP など)。

---

## 2. ミドル・エントリーの利点

| フェーズ                        | 公開ノート数 | 狙えるアドバンテージ                             |
| --------------------------- | ------ | -------------------------------------- |
| **開始直後**                    | 少ない    | 自前で模索、情報不足で手間増                         |
| **中盤 (残り 2–3 週間)**          | **最大** | 上位勢の特徴量・CV 設計を参考にできる。LB が安定する前に差別化も可能。 |
| **ラスト 1 週間 (Quiet Period)** | 減少     | 公開ノートが止まり新情報が得られない。提出回数・微調整勝負。         |

## 5. 技術スタック & 推奨レシピ

| フェーズ         | ライブラリ                                            | コマンド例 / 設定ポイント                                                    |
| ------------ | ------------------------------------------------ | ----------------------------------------------------------------- |
| **EDA**      | `pandas`, `pandas-profiling`                     | `profile.to_file('eda_report.html')`                              |
| **前処理**      | `scikit-learn` `SimpleImputer`, `StandardScaler` | 数値: Box‑Cox / Quantile 変換                                         |
| **モデル**      | `lightgbm`, `xgboost`, `catboost`                | LGBM: `boosting_type='goss'`; CatBoost: `loss_function='Logloss'` |
| **HPO**      | `optuna`                                         | `study.optimize(objective, n_trials=100)`                         |
| **解析**       | `shap`, `eli5`                                   | `shap.TreeExplainer(model).shap_values(X)`                        |
| **Ensemble** | `numpy` / 自作                                     | Optuna で重み探索 or 線形回帰係数                                            |

> **ベース Docker / Conda** は solid‑ml‑stack リポジトリの `docker-compose.yml` を利用。

## 7. リスク & 回避策

| リスク      | 兆候                   | 対策                                 |
| -------- | -------------------- | ---------------------------------- |
| リーク特徴量混入 | Public LB だけ異様に高い    | Feature Delete 試験 / 時系列 KFold で再検証 |
| 過学習      | CV と Private LB 大幅乖離 | Seed 変更モデルを平均化、特徴量削減               |
| 時間不足     | 連日 1 Sub すら出せず       | “最小ベースライン” Shell スクリプトで自動提出        |
